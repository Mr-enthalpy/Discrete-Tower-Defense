# 时序与结算

规则来自[基线第 01–07、11 章](../baseline/v1.0/README.md)。本文给出单线程固定步的**工程约定**；数字精度、算法性能和同一步边界均需规则夹具验证，不能当作已实现结果。

适用[用户修订 0003](../decisions/0003-敌人体型与白天保留战场.md)：进入白天停刷并一次复苏已毁非一次性塔，不清除敌人及既有战斗效果。未毁受伤设施不据此自动补满；已有敌人继续战斗，异常在场计数、技能进度与恢复窗保留。复苏不得直接删除敌人解决重叠。按用户修订 0004，先推挤，无法腾挪则持续双向碰撞伤害；正常伤害导致的死亡照常结算。黎明对核心和当时全部存活设施施加配置时长的无敌，敌人不因此免伤。

## 固定步阶段

| 顺序 | 工作 | 提交边界 |
| --- | --- | --- |
| 1 | 按序验证并提交命令；处理上步阶段开放 | 同步权限、占格、投资；失败不留部分修改 |
| 2 | 应用天气/阶段既定状态，更新失效空间/能源拓扑；普通军团与异常排程、生成及移动 | 预告锁定本轮范围强度；更新动态空间桶 |
| 3 | 形成真实工作请求与持续作用目标快照，求解本步供能并充电 | 源汇唯一、持续负载与充能竞争同一网络 |
| 4 | 生产/吟诵等非战斗工作，Q 入账逐笔检查阈值 | 对本步后续命令不追溯；已预告技能不变 |
| 5 | 推进武器机械冷却/节拍，复查目标与运行条件，提交合法动作 | 固定耗能原子扣除；电塔窗口释放；静电使用同一目标快照 |
| 6 | 弹体扫掠、到期爆炸/区域/关系、雷击、生命自耗、伤害和控制 | 稳定事件序，每事件固定真实命中集合；派生队列结清 |
| 7 | 对仍存活合法目标执行维修/净化，更新 C 和有效 A | 无效工作不消耗预留资源；实际净化回收才入 Q |
| 8 | 核心死亡判负；存活才执行阶段边界、黎明、胜利 | 白天关投放并复苏已毁永久塔，保留残敌与效果；不补能、不洗 C |
| 9 | 发布状态、规则事件与指标 | 下一步前只读；视觉不反向补规则 |

阶段 2 的移动完成后，阶段 3 静电取目标集；阶段 5 按同一集结算本步持续效果，期间不再移动或插入生成。前序死亡者跳过，不能临时把释放功率转给新增对象制造额外输出。下一步重建需求。充电后恰好满足单发能量，本步可发射。已发射效果不因来源断网撤回。

本步生产可提高 P，但新的投放等待公开窗口；在场异常记录待升级权限，当前技能结束后的下一轮应用。本步伤损立即撤销实体运行资格，后续事件不能使用其失效能力；已完成的充电不回滚，下一次网络求解必须使用更新拓扑。维修不能复活本步死亡目标。阶段边界开放对下一步生效。

工作可分“预留—提交—释放”：提前取得供能或 Q 使用许可，实际执行时目标失效则释放未消费部分；持续能量未使用时不能凭空存进无储能设备，也不能在同一步让多个系统重复使用。具体无储能未用能量计为未消耗供给；事件日志分清供给上限、分配、实际消耗。算法先保证守恒与无双花，不把预留额计为实际工作。

Q 入账先触发阈值，再允许后序消费；不可把同一步净收支相抵后跳过历史突破。多笔消费者竞争不足 Q 时暂用稳定工作序提交并记录停工原因（工程起点，需纯神秘场景验证）；这不改变电网的比例公平，也不新增玩家手动调度。

## 网络分配与三条曲线

每个需求上限为当前可工作需求 `d_i`，包括电容剩余空间/步长和最大连续汲取的较小值，或静电的 `N × p`。满储、停工、无需求退出。求解目标为网络可行约束下的**归一化最大最小公平**：渐进提高满足率 `a_i = x_i / d_i`，达到上限或实际瓶颈者固定满足率，其余继续提高，允许重新路由。普通最大流只能判断可达量，不自动给公平结果。算法是工程候选，需与小图参考解对照。

例如同瓶颈两个有效需求 10 和 30，总可得 20 时分配 5 和 15，均为 50%，不是 10 和 10。区域瓶颈不同可以产生不同满足率。真实源的总注入、汇的总接收和节点远程总出口分别限额；本地交换绕过远程口但不绕真实容量。重叠区和环路不能重复复制源或需求。

固定单发：网络增加本地库存，合法射击扣固定 q；无目标是否预充由能力定义，不能推导所有设施都同策略。电塔：最大连续汲取、有限库存，固定窗口低能也放电，零能不攻击；无目标保持储量且节拍继续，首次等完整窗口。静电：目标集产生需求，全部目标强度乘实得比例；不通过隐藏人数帽控成本。

电池充、放、待机互斥，优先补有意义的可达缺口，充电只用真实余量。初期不允许无目的电池互相倒电；具体区域模式须用瓶颈场景验证，不能把这一简化当最终平衡。每步记录源产出＝实际消费＋储量净增加＋明确损耗/弃能，放电也计入储量变化。暂停、治疗、黎明均不凭空增能。

雷击事件先捕获命中前网络，依据单次总能量与各接收接口/剩余容量分配脉冲，本地不占远程额度、跨区仍受额度；随后提交该雷击的中立伤害和断网。脉冲不是每接收者一份全额奖励，也不受普通连续汲取上限替代。连续供电与雷击都使用同一真实库存、剩余容量和统一能量账。

诊断分别提供长期产能不足、可达/远程传输瓶颈、储能容量/充放功率/库存不足的证据，可并存；单步请求峰值不能直接判长期发电不足。巨炮加入后其他消费者满足率和火力节奏的变化应可追踪。

## 伤害、移除与死亡

事件排序用计划 Tick、事件生成序号和稳定实体序，不用容器下标或动画回调顺序。每个爆炸事件按其实际时刻查位置，一次只命中每实体一次，不同事件可再命中。巨炮沿扫掠路径按先后命中，山体截断后不命中背后；同弹命中历史跨步保留，无不同目标数量帽。

伤害契约显式选择普通层盾策略、护甲策略和适用异常防护。普通包先外层盾，溢出耗散；穿层包向内连续，绕盾包进本体；本体再按护甲及已声明异常减伤/单包上限/共享窗口/免疫处理。异常防护作用于哪个阶段由其定义明确，不能把暂定统一管线解释成可以绕过原文防护。祛除额外真伤是独立包，效果资格在清洗前快照，清掉最后一点 C 不取消本次加成。

电塔使用伤害预算账：实际伤害、盾吸收、甲及异常耗散均从原预算扣除；只有目标死亡且预算尚存才向空间相邻目标传导，不把减免额重新当溢出。献祭/吞噬走独立资格和固定名额，不能凭外观小就吞异常；默认战斗死亡派生照常。

| 终结原因 | 处理 |
| --- | --- |
| 战斗伤害归零 / 合法自耗归零 | 依定义残骸、爆炸、终结仪式或召唤结束，恰好一次 |
| 特殊移除 | 资格与名额通过后，按定义默认战斗死亡派生 |
| 融合消费 | 投资/状态转移，不爆炸、不发动仪式、不发击杀奖励 |
| 出售 | 合法对象单次退款，不触发战斗死亡 |
| 显式终局清理 / 重开 / 卸载（不含日常黎明） | 不触发敌方死亡派生，不给击杀成长 |

阶段内产生的死亡效果进入稳定队列直到本批处理完；单实体终结标记保证一次结算。内容校验和明确生成预算防无限派生，不能运行时默默截断合法伤害。万魂幡只统计自身合法攻击击杀，不统计他杀、献祭和清场。

## 暂停与权限

暂停不推进生产、充能、自然/人工天气、仪式生命、技能预告/持续期、冷却和波次。可用工程操作仍走验证/提交，消耗库存并更新空间；锁定时拒绝。暂停不能快进解锁干扰，也不能绕掉部署冷却。终局只查看、重开和退出等宿主操作。

盲目、迷乱、缄默由模拟给出源、预告、锁定种类、起止 Tick、恢复窗；Godot 执行信息投影和反馈。普通关排程禁止长期连续三重剥夺，挑战覆盖必须关前公开。暂停、相机、设置、退出、辅助模式的宿主命令没有异常锁字段。
