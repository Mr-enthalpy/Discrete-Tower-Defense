# 状态与契约

工程约定，尚无对应 API 实现。依据：[基线第 01–07、10–11 章](../baseline/v1.0/README.md)。符号是设计名，不承诺此轮生成空类。

## 持久状态与运行状态

| 数据 | 内容 | 所属 |
| --- | --- | --- |
| DefinitionSet | schemaVersion、稳定 ID、单位、强类型能力、内容哈希 | Content 构造，Simulation 每局冻结 |
| WorldState | Tick、阶段、自然时钟、随机流种子/状态、命令序号、胜负 | World |
| ProgressionState | 金币、Q 库存、历史阈值档、T/M/P、卡槽、部署冷却 | Progression |
| EntityHandle | 槽号＋代数，另有稳定生成序号 | World；不能用连续数组索引保存引用 |
| FacilityState | 定义、V、位置/朝向、占格引用、HP、投资账、基础规格、C、成长历史 | 实体字段由所属系统更新 |
| EnergyState | 有限库存、容量、汲取/脉冲上限、源汇/覆盖/远程端口、电池模式 | Energy |
| FamilyPreparation | 家族 ID、工作进度、一个 ready 标记、关联读经阁 | Rituals；不按阁存重复资格 |
| UnitState | 类型 ID、体型变体 ID、普通/异常身份、军团、独立 HP/甲/盾/C、控制、行动状态 | Combat/Legions；净化不改种类 |
| AnomalySchedule | 投放预算、在场限制、施法轮次、预告参数快照、并发与恢复窗 | Anomalies；与动画进度无关 |
| EffectState | 弹体、爆炸事件、持续区域、关系、控制、来源与过期步 | Combat；有明确生命期和去重域 |

以上是逻辑拥有权，初期可同在一个 World 容器，不要求复杂对象网。Q 是当前可支出库存；历史阈值用单独字段追踪，不以累计流水代替。五阈值越级更新 M/P 时用 max 保留关卡独立初始权限。Q 生产、净化回收、献祭回收、背景泄露分别有来源，消耗也单独记账。

地形格存实际高度、移动许可、普通建设许可、耗物部署许可、区域和标签。建筑安装层、配方输入位置、输出足迹分开。支撑墩有效规格只用于承载/后靠，不写入地图高度。多格引用同一实体；装饰节点不加入空间查询。

## 内容定义

[修订 0003](../decisions/0003-敌人体型与白天保留战场.md)：EnemyTypeDefinition 保留职责/能力，SizeVariantDefinition 按类型列出支持的体型及数值修正/覆盖、碰撞与净空规格；不生成类型和体型的完整笛卡尔积。实例与保存记录类型＋变体，加载拒绝缺失组合。明确基值与覆盖的解析顺序，最终数值只算一次；不从渲染缩放或敌名推测属性。体型相关控制读取规则字段，特殊移除同时验证普通/异常资格。波次/补员引用合法组合，权重归属场景。

白天状态只关闭阶段投放并在进入时触发一次已毁永久塔复苏；存活敌人、弹体、技能与军团/异常账目跨日保存。生成请求区分关卡波次、异常投放、补员、门扉及死亡派生，避免一个清场开关误删残敌；后几类白天政策待明确。复苏阻挡冲突和最终胜利条件见修订待定项。

规则和数值唯一来源为根 `content/` 的未来 JSON。定义契约区分：设施、能力、升级分支、配方、仪式家族/成员、敌人、普通军团、异常排程、天气、地图、关卡与测试场景。场景不能重新复制塔价、攻击表；确需实验覆盖时显式标记 Fixture、记录内容哈希及覆盖项。

每个能力使用封闭的类型标记与对应字段，例如 `FixedShotEnergy`、`CadencedDischarge`、`ContinuousPerTarget` 是不同用能能力，不能仅靠一个能耗字段猜行为。攻击效果独立描述普通伤害、穿层、绕盾、绕甲、真伤、特殊移除及适用异常防护。新增真正行为才增执行系统；新增同类内容只增定义和呈现映射，不按中文名 if/else。

加载返回完整不可变包或带文件/字段路径的错误。检查 ID 唯一/引用、非法负值与单位、升级可达、严格递增阈值、V3 材料、2×2 等高条件定义、显式叠放、输出卡权限、仪式族/成员 M 条件、效果持续期、特殊移除对象资格、地图入口/阶段通路。拒绝未知行为，不把 JSON 变成任意脚本。

定义、场景和呈现映射分离；Godot 对稳定 ID 配置图元/纹理/音频，不承载第二份规则。每局冻结定义；开发重载下一次重开才生效。导出内容为可重建副本，不能依赖仓库外 Downloads 或原游戏资源。

## 命令事务

命令包括选择之外的规则操作：建设、安装、升级、融合、出售、仪式部署、阶段换卡、典籍切换等。宿主传世界坐标/朝向、目标句柄、请求 ID 和有序时间戳；相机角度不参与世界配方。

`Quote` 只读返回候选输入、输出足迹、完整费用、材料等级、运行条件和失败原因；报价不是预扣款。`ValidateAndCommit` 再检查最新实体代数、卡/T/M、当前交互锁、材料/等高/支撑、占位、敌人碰撞、金币/Q、准备资格与冷却。成功一次提交所有扣费、输入消费、输出创建、投资/伤损/C 继承和空间失效；任何失败全部不变。

特殊叠放配方先识别，随后才判一般占用冲突。融合输入可在输出足迹之外；祛除相邻双塔是明确用例。合成后等级通常 V0，消耗材料的实际投资只转入一次。伤损和 C 按最大 HP 权重继承，不借更换定义清洗；旧能力临态按输出规则清理，能量不得凭空增加。具体容量合并/溢出规则在配方字段锁定前必须给测试。

命令结果使用稳定原因码和结构化参数，例如缺权限、缺材料、非等高、支撑不足、余额不足、暂时干扰、目标已失效。前端本地化原因，不从字符串反推规则。异常期间非法请求立即拒绝、不缓存重试。普通选中、相机和软件控制不走建设许可。

## 输出、保存与回放

`FrameView` 提供只读实体状态、范围预览和可用命令；`SimEvent` 提供已提交的命中、收支、预告、阈值、死亡与阶段结果。规则事件不能因渲染预算丢弃；客户端可合并装饰。`PlayerInformationView` 根据元技能屏蔽精确值，开发追踪日志单独通道。

存档以后保存格式/规则/内容版本、稳定定义 ID、时钟、随机流、队列、能源、T/M/P/Q/阈值、C、准备资格、投资与成长历史；不保存节点树或可移动容器下标。加载重建句柄关系和索引。初期只需重开与可重放命令记录，不预建通用跨版本迁移器。

重开从场景定义重建全部世界，包括技能排程、仪式家族、冷却、自然天气、污染与随机状态。不得残留上一局异步事件、语音/装饰对规则的回调或旧句柄。
