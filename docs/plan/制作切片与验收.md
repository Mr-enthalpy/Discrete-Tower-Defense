# 制作切片与验收

依据：[基线第 09–10 章](../baseline/v1.0/README.md)。合并适用[用户修订 0003](../decisions/0003-敌人体型与白天保留战场.md)。A.5 已实施并通过当前 71 项检查；B–F 仍为计划。实际范围及未覆盖项见 [DEMO A](../../DEMO-A.md)。A–F 是制作切片；M、P、V 只用作游戏术语。

## 工程前置

实际验证 Godot .NET 编辑器、SDK、匹配导出模板、纯库引用与 Windows Release 在无 SDK 环境启动。记录版本组合再落地项目文件、锁文件和命令。形成三个程序集和最小无引擎规则测试，不安装与当前切片无关的框架。

## 性能与画面

人工夹具可从数百设施、上千敌人起测，但不作为关卡人数指标或性能承诺。记录硬件、版本、种子、负载、分辨率、速度、采样方法；观察每阶段 p95/p99、内存/GC、积压、真实候选/命中、电网求解、导航复用与绘制上传。覆盖密集拥堵、同时爆炸、雷击、死亡派生、断网和反复重开；不能只测平均 FPS。

纯 .NET 隔离规则成本，Godot headless 检查装配/资源，Release 导出检查完整 CPU/GPU 和实际画面。优化必须保持账目、完整 AOE、生命周期与异常排程。没有固定机器前不把旧毫秒预算作为验收成绩。

美术检查正常/最小缩放、密集战斗、建造选中、C 连续变形、P UI/BGM、盲目信息遮蔽和辅助模式；能辨认职责、甲盾、储能、缺电与预告。构件移动不改变碰撞，声音不偷偷提供盲目隐藏的完整精确数值。
