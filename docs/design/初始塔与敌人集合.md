# 初始塔与敌人集合

状态：初始内容提案 v0.1，2026-09-22。它把[参考机制登记](参考机制登记.md)的启发与[核心系统约定](核心系统约定.md)结合为一组可分期验证的内容；不是已实现或已平衡的配置。名称、ID与新增数值是本项目起点，之后按实际体验调整。

**范围与数量**

建议首轮核心机制集合为**10种设施（含核心）＋5种敌人**，储能塔单列为可选第11种设施。M0只做核心、哨戒炮和行进体；M0–M2完整基础闭环仍是既定的核心加五种普通设施、三种敌人。E1–E3逐步补齐其余职责，不改变“先小闭环”的开发顺序。

| 阶段 | 本阶段新增设施 | 本阶段新增敌人/行为 | 累计设施/敌人类型 |
| --- | --- | --- | --- |
| M0 | 核心、哨戒炮 | 行进体；推进核心、共享导航、独立接敌 | 2 / 1 |
| M1 | 挡墙、采掘站 | 使用同一种行进体组织三夜 | 4 / 1 |
| M2 | 爆破炮、维修站 | 疾行体、重装体；基础属性差异 | 6 / 3 |
| E1 | 支撑墩、山背巨炮 | 复用既有敌人；验证朝向与空间 | 8 / 3 |
| E2 | 发电站、无线供能塔 | 复用既有敌人；验证断网与供需 | 10 / 3 |
| E3 | 无 | 维生体、攻城手；疾行体增加袭击能源的组任务 | 10 / 5 |
| 可选储能切片 | 储能塔 | 无 | 11 / 5 |

设施总数始终包含核心：基础闭环为核心＋5种普通设施，E1–E3合计为核心＋9种普通设施，可选储能另计。这里按不同的内容定义计数，普通强化、场景参数和组任务不另算新塔或新敌人。下列ID是内容引用约定，不要求现在创建JSON、类或加载器。

**基础设施：沿用已有试跑参数**

| ID / 名称 | 对应试跑角色 | 职责与可见行为 | 引入阶段 / 来源 |
| --- | --- | --- | --- |
| `core` 核心 | 核心 | 胜负目标、保底金币、科技入口；E2再提供独立启动的小型源与无线覆盖 | M0；项目循环要求 |
| `sentry` 哨戒炮 | 单体塔 | 1×1，稳定单体弹体，近目标优先；负责基础防御并作为未来改建输入 | M0；T01 |
| `wall` 挡墙 | 围墙 | 1×1，被动承伤、阻挡，不耗能；只买时间，不自动提供巨炮支撑 | M1；S01 |
| `extractor` 采掘站 | 金矿 | 1×1，只建矿点，周期产金币；产出被损坏和以后缺能打断 | M1；S04 |
| `blast` 爆破炮 | 群攻塔 | 1×1，朝锁定落点发射并爆炸，范围内每个合法敌人完整受击一次；长周期留出空窗 | M2；借鉴多目标职责，真AOE自主定义 |
| `repair` 维修站 | 维修塔 | 1×1，单目标恢复生命比例最低的存活设施，包含核心；不救残骸。E2追加局部无线覆盖，恢复能力仍需耗能 | M2；S03，能源混合角色为自主补充 |

六种设施的金币、生命、攻击/恢复周期和强化值只在[试跑配置](试跑配置.md)维护，不在这里抄第二张基础数值表。普通强化仍是等级变化，不能替代消耗基础塔的改建操作。维修站在M2仅治疗，E2后才有能源角色变化。

地形规则按阶段生效：基础场景维持采掘站只建矿点，其余只建地面。E1地形场景开放哨戒炮建在山体上，作为“有的塔能上山”的代表；爆破炮、维修站、发电站、无线供能塔、支撑墩和巨炮仍要求普通地面。不额外给山上哨戒炮伤害加成，先只验证放置权限。山地阻挡地面移动，但不默认阻挡弹道；山上防线的平衡要在E3远程敌人加入后复查。

**E1：用两种新设施验证空间与改建**

| ID / 名称 | 足迹与取得方式 | 起始能力和代价 | 需要看到的结果 |
| --- | --- | --- | --- |
| `brace` 支撑墩 | 1×1；消耗一座存活挡墙原地改建，追加40金币；科技2 | 450最大生命，被动阻挡并提供 `heavy_backing`；不攻击、不耗能 | 普通挡墙不满足条件，改建后的支撑墩可以替代山体；继承投入和生命比例 |
| `backed_cannon` 山背巨炮 | 四座存活哨戒炮占满2×2方阵，追加260金币；科技2，改建部署冷却8秒 | 500最大生命；每4.8秒发射，伤害120、射程7、落点半径1.5、弹速8；朝向前方90°射界 | 一座实体占四格；原四座炮消失；背侧两格均有山体/支撑墩才开火，允许混用 |

这些是代表性配方，不是所有高阶塔的统一公式。巨炮使用完整真AOE，不叠加穿透、燃烧或强制眩晕。射界内最近目标优先，朝向按四向设置；炮口在前缘中点，射程与射界从该点计算。支撑失效不摧毁巨炮，但下一次发射前必须停火。敌人进入其他方向时，巨炮不能偷偷全向转炮。

两种改建都遵守原子消费、实际投入转移、生命比例继承和失败无副作用。支撑墩沿用挡墙2秒部署冷却；改建不因选中不同基础塔而绕过同类输出冷却。四座满级哨戒炮不是免费加强配方：其真实投入会被继承，但巨炮初始能力仍取自身定义，不把旧伤害叠加进去。

以未强化输入计，巨炮累计金币投入为660，支撑墩为70；两座支撑墩把无山体位置的完整配套投入提高到800。原四炮总基础单体DPS为60，巨炮单目标平均DPS为25；它要靠更远射程和多个目标命中兑现价值。这些只是不含命中、供能、空间和风险的比较基线，不能据此宣称已平衡。它同时有朝向、后侧占地、较长火力空窗和四格投资集中的弱点，数量无需硬上限。

**E2：供能角色与少量起始参数**

能源单位使用抽象功率P和能量E。以下参数仅在真实能源场景启用；M0–M2仍用 `TestSupply`，也不提前改变其金币数值。

| 对象 | E2能源角色 | 试验参数 |
| --- | --- | --- |
| 核心 | 源＋本地无线覆盖＋远程传输 | 保底供给6P，半径3.1，远程总转供上限6P；金币收入独立于电网 |
| `generator` 发电站 | 纯源，1×1 | 150金币、120生命、部署冷却5秒；持续产20P；需要接入无线区，无自带覆盖，起步不消耗运行电力 |
| `relay` 无线供能塔 | 本地无线覆盖＋远程传输，1×1 | 80金币、100生命、部署冷却3秒；半径3.1，远程总转供上限8P；没有自身发电，不预设自耗 |
| 维修站 | 用能汇＋本地无线覆盖 | 治疗需求4P，能源覆盖半径2.5；无远程输出能力，可以接收其他区转供；治疗停机不撤掉被动覆盖 |
| 哨戒炮 / 爆破炮 / 山背巨炮 | 纯汇 | 主动工作需求分别4P / 6P / 16P |
| 采掘站 | 纯汇 | 生产需求4P，缺能按实得比例推进产出周期 |
| 挡墙 / 支撑墩 | 无能源角色 | 0P，被动承伤/支撑不依赖供能 |

新建发电站和无线供能塔暂用科技1，E2不再新增科技层；需求4/6/16等数值都可调。发电站、无线供能塔和支撑墩暂不提供普通数值强化；巨炮也暂不增加强化分支，避免用内容数量掩盖基础规则。

需求来自有效工作意图：有合法目标及支撑的攻击塔申请工作功率，维修站有合法受伤目标才申请，存活采掘站持续申请。功率用于推进工作周期，不再于发射时二次扣能。目标/支撑/工作意图在分配前确认，实际发射仍二次检查有效性；本步新出现的目标允许下一步开始申请，不制造回溯补供。零供能暂停，部分供能减速，无目标按既定攻击计时规则处理。

本地源汇交换不占无线塔8P远程额度；跨区输送才占。一个区放三座哨戒炮需求12P，区内发电站可全额供电；若同样三座炮只能从外区通过一座8P转供节点获得能源，就存在4P缺口。维修站的局部覆盖让一座塔体现消费与连接的混合角色，但它不能自动转送能量到第三个区。重叠覆盖遵守独立注入/消费和总量约束，不复制源或汇。

E2场景必须显式选择真实能源模式，并重新分配初始金币/建设方案，不能拿M2的开局资源直接断言电网可解。空间规则夹具可以预放满血设施并禁用经济；经营场景则保留真实付费与部署冷却，两者的结果分别记录。

**可选：一座储能塔先验证昼夜调度**

`battery` 储能塔先设1×1、120金币、80生命、部署冷却3秒、科技1，仅建普通地面，初始储量0、容量300E、最大充电5P、最大放电4P，不自带无线覆盖或远程转供。白天作为汇接收余量，夜间作为源，单步不同时充放；与普通源、汇使用相同覆盖和流量约束。

常规发电站在E2持续供能，储能试验场景才把其发电曲线改为白天20P、黄昏/夜间0P，用来验证“白天发电、夜间放电”。这只是场景变体，不把所有发电站永久改为日照发电；若该玩法成立，再决定是否新增专职太阳能塔。75秒夜间缺口4P需要300E；远程充电速度不足时，扩大容量本身不能解决问题。恢复、损坏和出售遵守系统约定，不凭空补电。

**敌人：三种基准、两种战术角色**

| ID / 名称 | 基础行为 | 玩家要处理的问题 | 阶段与参考关系 |
| --- | --- | --- | --- |
| `marcher` 行进体 | 向组目标前进，接触设施后攻击 | 普通持续压力；检验直射和真AOE | M0；E01，仅借鉴可辨识的基础敌人职责 |
| `runner` 疾行体 | 低生命、高速度；M2仍向核心推进 | 火力空窗、转火速度和薄弱方向 | M2；自主速度配置，非原形状技能映射 |
| `heavy` 重装体 | 高生命、慢移动、高接触伤害 | 持续单体输出和前排耐久 | M2；E01；无硬限伤、无AOE减伤、无同伴护盾 |
| `sustainer` 维生体 | 跟随同组战斗成员，周期治疗附近受伤同伴 | 优先击杀支援、阻止重装反复恢复 | E3；E05，具体跟随/治疗自主定义 |
| `siege` 攻城手 | 移动到目标设施射程内停下，发射慢速单体攻击 | 后排、山上阵地、无线供能节点不能只靠前排杂兵清除来保全 | E3；本项目自主补充，不假称来自原作某种外形 |

前三种的生命、速度、伤害和波次预算只在试跑配置维护。E3新增的起点为：

| 敌人 | 生命 / 移速 | 主动能力 | 场景预算成本 |
| --- | --- | --- | --- |
| 维生体 | 80 / 0.75格每秒 | 范围2.5内每2秒治疗12，仅同组存活战斗成员，最低生命比例优先、等值按ID；不能治疗自身或其他维生体，不复苏 | 5 |
| 攻城手 | 100 / 0.5格每秒 | 射程5，每3秒28伤害，弹速6；发射时锁定设施位置，命中沿途首个存活玩家设施后消失；可跨山但不穿建筑 | 8 |

维生体由组级跟随目标引导到前排后方约1.5格，个体继续局部避让，不传送或无视地形。进入接触自卫时暂停治疗，以每1.2秒6伤害攻击接触设施；两种能力不同时出手。失去全部可支援战斗成员时回退为推进核心。攻城手目标失效时重新接受组目标，不对残骸持续射击；第一次开火仍等完整间隔。

重装体只用高生命和接触承压验证质量基准，不声称它能替同伴挡住所有AOE。敌人都独立受击，真爆炸内的维生体照常受伤。维生体能否活在炮圈外、攻城手能否逼玩家调整火力，必须由我们的场景证明，不能依赖隐藏免疫或凭空加血。

**兵团模板复用单位，而不是制造更多种类**

| 模板 | 固定起始组合 | 组命令与角色分工 | 对照验证 |
| --- | --- | --- | --- |
| 基准杂兵 | 12行进体＋1疾行体，预算25 | 同入口推进核心 | 用于展示真AOE清理密集低生命目标的收益 |
| 重装支援 | 2重装体＋4行进体＋1维生体，预算25 | 重装推进、维生跟随同组前排，保留队内局部间距 | 相同单位与属性，关闭治疗再重放，比较有效治疗、突破与维生体存活时间 |
| 攻城纵队 | 2重装体＋2攻城手，预算28 | 重装接触前排，攻城手在自己射程停留；共享组任务，各角色目标区域可不同 | 保持人数和属性，比较直接推进与角色停距命令的防线损坏位置 |
| 能源侧袭 | 一侧4行进体＋1重装体；另一侧4疾行体，总预算18 | 正面推进核心；侧组攻击一个已预告的无线供能节点，失效/不可达则回退核心 | 同人数同属性，将侧组目标改为核心；比较断网时刻、受影响塔与停机时长 |

模板是独立E3场景，不直接插入M2循环选兵算法。预算相同不意味着威胁相等；只把前两组设为等预算起点，其余用于机制对照。黄昏可预告来袭方向和任务类型；侧袭目标由组级决定，个体不各自做全图设施搜索。兵团内不同角色可以申请不同导航结果，相同需求仍共享，不能强迫所有成员播放一条轨迹。

**最小验证顺序**

1. M0只用核心、哨戒炮和4个行进体，验证交战、共享导航、死亡与重开。
2. M1–M2沿用三夜试跑配置，补齐金币、挡墙、生产、真AOE、维修和三种基础敌人；这是基础闭环，不代表五项扩展都完成。
3. E1单场验证四座哨戒炮组合、两格背侧支撑、转向停火、山地放置权限；再以真实金币账目验证投资继承和出售。
4. E2单场验证纯源、纯汇、连接设施和混合维修站；对照本地12P交换与跨区8P限流、移除节点后的停机，确认维修站可服务本区消费者但不能远程转发到第三个区。储能另用昼夜场景。
5. E3用上述固定兵团模板检验质量压力。至少解释一个“数量不变，只改变角色协同/目标就改变防御结果”的案例，记录完整事件，不把增加刷怪预算当作验收替代。

当前不增加独立减速塔、穿透炮、燃烧塔、增益塔、自爆兵或分裂兵。若阵容验证后仍只有堆哨戒炮和爆破炮一个答案，再从机制登记中挑选明确能填补缺口的内容。
