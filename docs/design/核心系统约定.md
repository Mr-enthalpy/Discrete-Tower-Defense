# 核心系统约定

状态：启动设计 v0.2，2026-09-22。本文细化 [项目启动框架](项目启动框架.md) 的五项长期约束；尚未实现这些系统，也未完成平衡验证。

用户确定的是玩法方向：基础塔作为部分高阶塔的前置、至少支持1×1和2×2、地形影响设施功能、单货币与实时能源、真群伤、可发展为兵团的敌人组织。能源采用覆盖范围组网的源汇流模型，塔允许单一或混合角色；无线供能区内的本地交换不占远程传输额度，储能作为可选扩展支持昼夜调度。下文的具体配方、缺能分配、邻接数量和兵团职责是我们的**起步方案**，可以通过原型修改，不是已经确认的最终内容。

**分期与必须保留的边界**

| 系统 | M0必须具备 | 后续实际玩法 | 现在无需实现 |
| --- | --- | --- | --- |
| 占地与改建 | 设施实体与占用格分离；足迹、锚点、朝向；整组占用提交 | E1基础塔转换/组合、多格大塔 | 完整配方编辑器、所有异形足迹 |
| 地形与条件 | 建造合法性、运行许可、开火许可分开；查询返回失败原因 | E1山地建塔、背侧支撑、转向 | 万能条件脚本和全部环境交互 |
| 货币与能源 | 金币一个余额；主动能力通过运行/动作许可入口；源/汇/无线覆盖/远程传输可组合，本地与远程流量分开 | E2覆盖组网、源汇流分配、缺能管理；其后可加储能昼夜调度 | 流量求解实现、储能玩法、输电损耗 |
| 真群伤 | 伤害按实体结算，空间查询不与表现绑定 | M2首个真范围攻击；E3用质量压力调平 | 所有元素伤害、复杂抗性体系 |
| 敌人组织 | 每个敌人独立且有行动组归属；组目标和共享导航分离 | E3混合兵团、多个行动目标与角色 | 阵型编辑器、高级战术规划 |

M0只使用1×1塔、一种敌人和测试供能。用2×2无美术数据夹具验证空间表示即可。配方执行、电网经营和兵团战术分别随E1–E3落地，不因“将来会用到”而先造完整框架。

**一座塔是一份实体，可以占多格**

设施定义提供局部足迹、允许朝向、碰撞轮廓、炮口与能力范围参考点。实例保存实体编号、锚点、朝向、生命、能力状态和投入记录。朝向先采用上、右、下、左四向；足迹旋转后归一到包围盒左下角，锚点指该位置。地形条件、炮口与能力范围使用相同变换，避免图形转了、判定仍留在原处。

所有占用格指向同一个实体；点击任一占用格都选中整塔，出售一次清理全部格子。2×2不意味着四份生命或四份退款。足迹决定预留空间，碰撞形状可以略小，但不能允许敌人从多格塔内部穿过。范围查询即使通过多个格子或碰撞体找到它，也只返回一次合法受击实体。

建筑位置不等同于任一单格中心。距离和发射使用定义的功能参考点；多格塔的炮口、碰撞面、支撑检查位置分别由自己的几何定义决定。M0内容可以恰好都在中心，调用者不能依赖这个巧合。

**基础塔改建与数值强化是两种操作**

普通强化只改变现有实体的参数。改建配方描述输入塔、相对位置、允许等级/状态、输出足迹、金币追加费用和输出朝向。默认方案是**消耗并替换场上的指定基础塔**，不是检查全地图拥有若干座塔。后续若确实需要保留式前置，应作为另一种明确规则加入。

代表性试验配方可以是：四座基础炮座构成2×2方阵，追加金币改建为一座2×2巨炮。也允许一座1×1基础塔原地转换为另一座1×1塔。这里的“四座”和具体塔名只是验证案例；框架不把它们写死，也不为高阶塔设置常规同类数量上限。

配方报价和实际提交共同检查：

- 指定输入塔身份、位置、等级与方向符合配方，均存活且可被消费；核心不能作为输入。
- 输出完整足迹在地图内、地形许可；足迹内只允许指定输入塔或空格，不能吞掉无关设施、残骸或活敌人。
- 输入和输出的对应关系明确；初版要求输入占格在输出足迹内。若以后允许外部设施参与，必须另设显式规则。
- 金币、科技和部署冷却满足要求，所有引用仍指向报价时选中的有效实体。

执行时重新校验，一次性扣除追加金币、移除输入、创建输出、转移投入账目、替换所有占格并启动相应冷却。任一条件失败，地图、余额、输入塔和冷却全部保持原状。用一个局部事务完成即可，不需要通用事务引擎。

输出投入为各输入的实际金币投入之和加本次追加支出；旧实体账目同时注销，不能两边都可退款。默认不以改建免费治疗：输出生命比例沿用“输入当前生命总和÷输入最大生命总和”，向下取整且存活输入至少生成1生命；配方未来可以明确另设修复费用。新攻击能力等待完整首次攻击间隔，不在提交时额外射击。金币折扣、强化和后续出售都引用实际支付记录。

**地形、供能、开火分开判断**

| 判断 | 例子 | 不满足时 |
| --- | --- | --- |
| 能否建造 | 占地、地形适配、输入塔、价格、科技 | 拒绝命令，预览标出原因 |
| 能否运转 | 存活、得到所需供能、未被停机状态禁止 | 保留实体，暂停相关主动能力 |
| 能否开火 | 合法目标、射程、射界、冷却、背侧支撑 | 保留已建塔，显示缺少的开火条件 |

地块分别提供地形类型、功能标签和各移动类型的通行性。山体可以不允许地面敌人通过，同时允许特定设施建造，并提供重型支撑标签。这三件事不能合并成一个“可用格”布尔值。若以后改变地形，不能静默删除原有塔；应重新判定能力并应用明确的地形变化规则。

以2×2巨炮为例：坐标向上为北，朝北时占用锚点加(0,0)、(1,0)、(0,1)、(1,1)，背侧检查锚点加(0,-1)、(1,-1)。起步方案要求这两个位置**都**提供 `heavy_backing` 标签；每格可由山体或该格上存活的支撑设施提供，混用也成立。朝向变化同时旋转背侧检查位置和射界。

E1可以单独使用8×8测试地图：四座基础炮座位于(3,3)、(4,3)、(3,4)、(4,4)，改建为朝北巨炮；(3,2)、(4,2)放山体，或其中一格改为普通地面上的被动支撑设施。该案例用于验证空间与条件，不要求M0–M2试跑地图提前容纳全部朝向案例。

支撑查询面向能力标签，不写成“只接受某个山体名称”。支撑设施可能自身占多格，但不能靠巨炮自己的标签给自己提供支撑；残骸不提供支撑。E1先使用被动支撑设施，避免同时引入供电依赖环。以后若支撑设施也需电，则先完成供能判定，再派生有效支撑与开火许可。

默认允许玩家先造缺少支撑的巨炮，但预览和详情明确提示它不能开火；塔的特定配方也可明确要求建造时就满足支撑。拆掉山后的支撑设施或转向后失去支撑，只阻止之后的开火，已经射出的弹体继续存在。转向是需要重新校验足迹和条件的命令，不能仅旋转图片。

建造预览同时显示输出足迹、将消费的基础塔、追加费用、背侧检查格和射界；运行中区分缺支撑、缺能、损坏和普通冷却。玩家必须知道该补什么。

**金币用于投入，能量用于持续运行**

金币是建造、普通强化、科技和改建的唯一货币。能源使用单位时间供给、需求和流量表示，不是第二个升级钱包。电网建模为**覆盖区内交换＋覆盖区间限流＋源汇流分配**。无线供能表示连接方式，并不表示无限产能；不铺实体线路，不模拟电压、传播延迟或逐段损耗，也不预设每个中继都必须额外自耗。

塔的能源角色由能力组合表达，不用互斥的“发电塔类/用电塔类”划分：

| 能力 | 参数与作用 | 可组合示例 |
| --- | --- | --- |
| 源 | 注入供给功率 | 发电设施；发电兼攻击塔 |
| 汇 | 提取运行需求 | 普通攻击塔；维修兼无线供能塔 |
| 无线覆盖 | 建立本地交换区，使范围内源与汇接入 | 纯无线供能塔；发电兼无线供能塔 |
| 远程传输 | 在无线供能区间转送能量，受远程流量上限约束 | 无线供能兼中继塔；耗电兼中继塔 |
| 储能（可选） | 保存能量，充电时为汇，放电时为源 | 纯储能塔；无线供能兼储能塔 |

源和汇可以同属一座塔，但消费和注入分别记账；同一份能量不能既驱动自身又完整转供下游。纯源可以通过别的无线供能塔接入本地区，无需自带传输能力；纯汇只消费，不自动成为中继。围墙和被动支撑可以完全没有能源角色。

每座有效无线供能塔形成一个本地交换区。范围包含哪些设施的接收参考点，哪些设施就能接入该区；起步使用塔中心和圆形范围，2×2也只接入一次。同一区内的源→汇交换不经过该无线塔的远程限流口；“不限本地交换”仍受发电功率、需求和储能状态约束。

远程交换发生在本地交换区之间。起步沿用覆盖规则：具备远程传输能力的A覆盖到无线供能塔B的参考点，便允许A区→B区转供；反向连接另行检查。A的远程流量上限约束它向所有其他区转供的总和，不是对每条出边各给一份额度，也不限制留在A区消费的能量。接收到的能量若继续向下一层转供，还需经过下一座传输塔的限流口。覆盖半径先共用一个参数，不增加手动接线或另一套距离系统。

实现上可把本地交换区表示为虚拟节点：源经注入端接入区，区经消费端连接汇；区与区之间的边通过独立远程限流口。超级源到每个源的容量为其供给，每个汇到超级汇的容量为其需求。本地边不额外限流，远程口单独设容量。混合塔的注入端、消费端和转供端在求解图中分开，但仍属于同一个游戏实体，避免将全部本地用电误塞进远程容量约束。

重叠覆盖不直接把两个区合并为一个无限流量区。源或汇可以接入多个覆盖区，但共享同一份总发电上限或总需求，不能重复计算。普通源、汇及其混合塔的端点不承担穿透转供：收到的能量只能满足消费，不能不经限流就从另一个接入点原样发出。这样重叠区的源可以直接服务两边，但普通用电塔不会成为绕过远程限流的桥梁。

对交换区满足“流入＋实际注入＝流出＋实际消费”，实际注入不超过供给，实际消费不超过需求；接入边与传输边都遵守流量守恒。闭环不会产生能量，断开的分区不能共享产能。基础源头可独立启动，核心保底金币收入独立于电网。E2先验证无储能版本，多余可用产能不必全部注入。

图只在新建、移除、失效、复苏、位置或范围变化时更新；供给与需求变化时更新容量和分配，不要求每步从头构图。先以满足可达需求的流量求解为基础；供不应求时采用稳定、可复查的分配顺序，起步按固定优先级与实体编号优先满足消费者。具体算法在E2落地，M0不实现求解器。

供能结果返回需求、实得功率和原因，而不是只有一个永久通电布尔值。起步建议主动能力按实得/需求比例推进工作计时，零供能就暂停；避免把部分流量分给多个消费者后却全都禁止运行。该比例规则是可调的能力层决定，不影响源汇流模型；若以后需要满功率才能开火的特殊塔，再单独约定充能或分配门槛。

停机不积攒产出，恢复后不补射停机期间的弹体；独立的部署冷却继续按单局时间推进。攻击目标失效仍按目标规则重置攻击计时。已发射弹体、被动碰撞、生命和承伤不因停电消失。伤害导致的断网从下一模拟步发射前生效；玩家命令造成的连接变化在本步分配前生效，与主框架一致。混合塔的无线覆盖和传输能力起步视为被动，不能因为它自身的攻击缺电就切断下游，除非未来内容明确增加该条件。

一个E2数值夹具：无线塔A在(3,3)、B在(6,3)，覆盖半径均为3.1；A远程传输上限为3。发电塔在(1,3)、产能20，本地用能塔在(3,1)、需求12；远端用能塔在(8,3)、需求6。发电塔和本地用能塔只在A区，远端用能塔只在B区，A覆盖B形成区间连接。本地12可以全额满足，A→B最多转供3，远端仍缺3；不能因A上限3而把本地12也限制为3。此例只验证规则，不作为正式平衡数值。

**储能作为时间上的源与汇**

储能是可选的E2后续切片，不纳入M0。框架区分能量存量与功率：储能实例保存当前储量E，定义提供容量C、最大充电功率和最大放电功率。充放电通过同一网络参与流量分配，不能跳过覆盖关系或远程限流。

起步使用无损储能，每步时长为Δt：充电需求至多为 `min(最大充电功率, (C-E)/Δt)`，放电供给至多为 `min(最大放电功率, E/Δt)`；以实际流量更新 `E' = E + (实际充电功率 - 实际放电功率) × Δt`。初版同一储能塔每步只能充电、放电或待机，避免自己给自己充电的循环。求解使用步初储量决定边界，暂停不改变储量；以后确需损耗再加效率参数。

最初调度可直接跟随昼夜：白天发电源提供阶段相关功率，先供常规用能，再用余量充电；夜间储能转为源。阶段变化只改变供给或调度模式，不凭空补满电池。新建储能初值为0，黎明修复保留既有储量，出售不返还能量；损坏时停充停放，起步保留储量以便黎明恢复。若以后改为损坏漏能，应明确成为玩法规则。

本地电池向同一区的塔放电不占远程额度；从另一地区充电或向另一地区放电要走相应限流口。重叠覆盖下电池不充当同一步无上限的穿透中继，分时搬运能量仍受它的容量与充放电功率约束。

例如夜间75秒、当地持续缺口4功率，需要至少300能量和4放电功率；白天60秒内充入这300能量，还需要平均5功率的可达余量及至少5充电功率。若必须跨区充电且远程上限只有3，60秒最多充180，单纯加大电池容量也无法填平缺口。该例子把日间生产、远程输电和夜间储备联系起来，所有时长与数值均可调整。

M0–M2显式启用 `TestSupply` 场景模式：通过相同许可入口为试跑设施提供全额运行许可，不运行能源账目和网络。调试信息标明“测试供能”；它不是正式内容的零能耗设定，也不声称验证了能源平衡。E2先验证本地交换与远程限流，再按需加入储能和昼夜供电场景。

**真范围伤害与敌人质量**

范围爆炸在命中时获取范围内的候选，按真实碰撞形状检查，按实体去重，再以稳定顺序给全部合法对象结算伤害。一次攻击的命中集合使用同一时刻快照；伤害结算新产生的实体不自动加入这次爆炸。没有隐含人数上限，不按目标总数均摊伤害。以后可加入按距离衰减，但应在能力说明中表达。

特效、音效和伤害数字可以限流，命中与战斗结果不能限流。调试记录同时展示候选数、合法目标数、实际命中数，能检查多碰撞体重复命中或表现丢失。空间索引减少无关对象检查；一次确实命中很多敌人仍需要相应结算工作，不能假设真AOE成本与人数无关。

质量压力优先来自不同单位相互配合和不同目标，不默认给所有高级敌人范围免疫。候选职责包括：顶住正面火力的重装单位、在不同距离停留的攻城单位、需要优先打掉的支援单位，以及试图破坏无线供能节点的机动单位。它们都沿用独立生命和动作，只由行动组决定任务，具体能力逐个实现。

E3至少比较三种场景：密集杂兵让真AOE兑现价值；重装与支援配合迫使玩家分配火力；两个方向的行动组分别压制正面和攻击供能。先以相近部署预算做对照，记录突破、有效伤害与停机时间，再调预算。预算成本是人为的平衡参数，不假设“同成本”天然代表等威胁，也不只靠提高血量抵消AOE。

E3场景固定入口分布、组目标和支援对象，记录“支援存活多久、贡献多少有效治疗/增益”“何时破坏哪个能源节点、导致哪些塔停机”等事件。保持人数与基础属性不变，关闭协同命令或优先消灭支援再对照，判断威胁是否确实来自角色与行动。这些不是M2三种基础接触敌人的验收责任。

**波次、兵团、导航、个体是四层职责**

```text
波次：决定何时、在哪里投入哪些行动组
  行动组：决定任务、目标区域、成员角色和何时换方案
    共享导航：为相同导航需求提供方向场或路线走廊
      个体：读取导航、局部移动与避让、接敌、攻击、受伤、死亡
```

一波可以从多个入口放出多个行动组，不必整波绑定一个兵团。一个组可以混合不同单位；同组各角色若有不同目标或通行条件，可以使用不同导航结果。不同组若目标与通行需求相同，也能复用同一结果。兵团关系不能替代个体实体，组控制器或指挥单位失效时，成员执行后备命令，不连带删除。

M0只需一个“推进到核心”的组级命令，按核心目标生成共享方向场。可用BFS处理等代价地图，增加代价后再考虑Dijkstra；不要求先实现两套。个体读取当前位置的推荐方向，结合附近敌人与设施处理局部运动和接触攻击，不为每个敌人保存独立完整路径，也不按预制曲线播放位置。

导航缓存键应表达目标区域、移动类型/体型通行需求、导航策略和相关地图版本。V0采用静态地形导航、遇到设施就攻击的攻城策略；建筑变化影响接触和局部碰撞，但不必因此重算无关的静态场。以后避障、绕行和寻找突破点可使用包含设施代价的其他策略，只有受相关变更影响的结果失效。

组级决策由事件或较低频率更新，不必每个模拟步重选全图目标。个体移动、碰撞与战斗仍需持续推进，局部邻居通过空间索引查询；共享寻路减少的是全局路线计算，不会消除随敌人数增长的局部工作。拥堵时由个体先处理，持续卡住才反馈组级重规划或改变破障目标，不能靠每个单位不断跑全图寻路或瞬移解决。

停滞探针初试为：有移动命令且未接敌/集结等待的单位，连续3秒位移不足0.1格，记录位置、局部阻挡者与组目标；同组反馈合并，不能逐个触发全图重算。这是可调的异常观测阈值；性能场景需检查持续停滞与重规划次数，不能仅靠减少生成量掩盖局部移动问题。

E3先做少量明确的组命令，例如推进核心、攻击指定能源节点、在集结区域等待、失去目标后转攻核心。专职单位根据角色选射程和位置；无需第一次就做完整阵型或通用战略AI。性能观测分别统计组级决策数、导航实际计算数、复用数和个体局部更新耗时，避免用“分了兵团”代替真实收益。

**切片验收与框架完成的含义**

| 阶段 | 最小代表案例 | 必须成立的结果 |
| --- | --- | --- |
| M0结构验证 | 1×1交战，2×2空间夹具，多个单位共享核心导航 | 单实体多格占用；非法占格不部分提交；单位独立受击，导航复用；运行许可没有被绕过 |
| M2真群伤 | 同一范围分别放10个与100个合法目标，并包含多碰撞体目标 | 全部各命中一次，伤害不随人数被摊薄；限制表现数量不改变结果 |
| E1空间与改建 | 基础塔组合为2×2炮；两格背侧由山体/支撑塔提供 | 正确消费输入和继承投入；非法组合无副作用；转向后重查足迹/支撑；拆支撑停火；出售整塔一次 |
| E2能源经营 | A区本地需求12、远程限流3，B区需求6；再加入混合角色与重叠覆盖 | 本地12不被限流为3；远端至多取得3；混合塔和重叠覆盖不重复发电/消费、不绕过远程限流；断网结果可解释 |
| E2可选储能 | 日间充电、夜间补缺口；远程充电受限对照 | 实得流量改变储量；容量与充放电功率独立限制；不能同一步自充自放；暂停/黎明/重建不凭空产生能量 |
| E3质量压力 | 混合兵团与分路攻击供能 | 角色可有不同目标、共享相容导航；失去目标有后备行为；真AOE有效但不能独自解决所有威胁 |

上述为未来实现的验收约定，不是已经运行通过的测试。M0完成只代表最小交战和可扩展的数据边界成立；E1–E3完成后，才有资格判断这五项机制是否共同产生了我们要的游戏体验。
