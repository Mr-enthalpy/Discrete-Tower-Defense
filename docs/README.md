先读启动框架建立全局认识，再读系统约定；内容选择读取初始集合，基础数值读取试跑配置。系统约定细化启动框架，初始集合与试跑配置服从这两份规则；基础参数只在试跑配置维护，E1/E3a/E2/E3b新增参数暂在初始集合维护。机制登记是来源与候选库，不直接定义游戏行为。发现冲突时修正相关文档，不用“后读到的文件”默默覆盖已有决定。

当前已确定体验方向、五项机制、无线能源模型，以及Godot .NET＋C#、JSON内容和SVG/纹理资产路线。技术架构承载玩法规则，不覆盖系统约定；精确工具链需首次工程验证。既有参数及示例都是验证起点，没有游戏运行结果。

接下来验证并锁定工具链与Windows导出，再实现M0最小交战和初始规模探针。M1–M2验证完整基础循环；内部顺序为E1多格与地形→E3a测试供能下的战术敌人→E2真实能源→E3b能源侧袭；电池峰值缓冲与昼夜调度是E2后的可选切片。关卡按经营、防御与综合三种压力配置验证。完整范围及验收以设计文档为准，不在多个计划文件重复维护。

影响跨模块边界的重要选择可在需要时新增 `docs/decisions/NNNN-主题.md`，简述背景、决定、代价、验证方式和取代关系。现阶段不预建一批空决策文档，也不把所有日常修改写成决策记录。
