# 文档导航

本目录是新项目的设计依据。原资料目录中的旧报告保留作历史记录，后续修改以本仓库为准。

| 文档 | 职责 |
| --- | --- |
| [项目启动框架](design/项目启动框架.md) | 项目定义、核心循环、美术规范、模块边界、阶段与验收 |
| [核心系统约定](design/核心系统约定.md) | 五项长期约束及能源补充的具体模型；实现边界与代表案例 |
| [首轮试跑配置](design/试跑配置.md) | M0–M2基础闭环的初始参数，显式测试供能 |
| [参考机制登记](design/参考机制登记.md) | 原作塔/敌人的机制线索、出处与可信边界，以及本项目的取舍 |
| [初始塔与敌人集合](design/初始塔与敌人集合.md) | 首批内容ID、职责、阶段、少量新增参数与兵团验证场景 |

先读启动框架建立全局认识，再读系统约定；内容选择读取初始集合，基础数值读取试跑配置。系统约定细化启动框架，初始集合与试跑配置服从这两份规则；基础参数只在试跑配置维护，E1–E3新增参数暂在初始集合维护。机制登记是来源与候选库，不直接定义游戏行为。发现冲突时修正相关文档，不用“后读到的文件”默默覆盖已有决定。

当前已确定体验方向、五项机制和无线能源模型；尚未选定引擎、语言、内容格式和资产管线。既有参数及示例都是验证起点，没有游戏运行结果。

接下来先记录技术选型，再实现M0最小交战。M1–M2验证完整基础循环；E1–E3分别验证多格与地形、能源经营和兵团质量，储能是能源后的可选切片。完整范围及验收以设计文档为准，不在多个计划文件重复维护。

影响跨模块边界的重要选择可在需要时新增 `docs/decisions/NNNN-主题.md`，简述背景、决定、代价、验证方式和取代关系。现阶段不预建一批空决策文档，也不把所有日常修改写成决策记录。
